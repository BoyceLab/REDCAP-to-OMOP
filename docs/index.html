REDCap to OMOP mapping wizard

Map a REDCap registry to the OMOP Common Data Model v5.4, check every concept id against your own vocabulary download, and export the files the runner needs. Everything happens in this browser tab; nothing is uploaded.

Start from your data dictionary

In REDCap: Project Setup, Data Dictionary, Download the current Data Dictionary. It holds field names, labels and answer codes, and no patient data.

Check every concept id against your vocabulary

Choose CONCEPT.csv from your OMOP vocabulary download (athena.ohdsi.org, free with an account). The file is about 1 GB; this page reads it from your disk in a stream and keeps only the rows for ids your mapping uses. It takes a minute or so.

With CONCEPT_RELATIONSHIP.csv (about 2 GB) the check also proposes the standard concept each retired or non-standard id maps to. Choose it before CONCEPT.csv.

Rules: an id must exist in the release, be valid and standard, and belong to the domain of the table it is written to. An id used for two different answers is flagged, and so is a label that shares no words with the vocabulary's name for the id, because that is how a mistyped id usually shows itself. After a check, the name columns carry the vocabulary's own names.

Export

Run it on your export

Export your data from REDCap as CSV, raw data (codes, not labels). Then, with Python and pandas installed, on the computer where the data is allowed to be:

python runner/redcap_to_omop.py --project project.json --mapping mapping.csv \
    --export your_export.csv --check

python runner/redcap_to_omop.py --project project.json --mapping mapping.csv \
    --export your_export.csv --output omop_output

The first command checks the export against the mapping and writes nothing. The second writes one CSV per OMOP table and a qc_report.md.
